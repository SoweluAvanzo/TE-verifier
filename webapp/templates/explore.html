    Average balance per role over time

    One line per agent_type. Tells you which roles accumulated balance and which gave it up; useful for spotting wealth flow from one role to another.

    Balance-share per role over time

    Each role's fraction of total tokens at every period. Aggregates to 1.0. If one line steadily climbs, that role is consolidating wealth at the expense of the others.

    Population aggregates (Gini, φ)

    Balance Gini and delegate-power Gini diverge under DELEGATED voting; φ tracks the fraction of agents that acted recently. Higher Gini = more concentration; higher φ = healthier participation.

    Action mix per period (population-wide)

    Stacked area: what fraction of all agents picked each action this period. Surfaces behavioral regime shifts (e.g. "everyone stopped earning at t≈50").

    Live population over time (Phase E1)

    Active agent count per period. Flat line when exit is disabled; downward slope means UtilityWeights.exit_propensity > 0 is firing — agents whose scalar utility falls below the population mean are leaving.

    Reputation over time (Phase E3)

    Mean reputation across the population, plus per-role breakdown when distinct. Reputation accrues on EARN/VOTE and decays each period by UtilityWeights.reputation_decay. Zero line means no type opted into reputation tracking.

    Event occurrences over time

    Per-period firing count of every event declared in te.events. Spikes signal demand surges; flat lines indicate stationary frequency. Cross-reference with the supply chart above to spot mint/burn drift.

    Non-tokenized asset flows

    Per-asset inventory count, cumulative created and cumulative consumed. Tracks good/service purchases driven by token redemption. One line per (asset · metric).

    Failure-mode coherence (verifier vs ABM)

    For every safety predicate the verifier emitted, the ABM-realized trajectory is checked against the same threshold. Flags where simulation and static analysis agree, where the ABM exposes a corner the verifier missed, and where the verifier was conservative.

    Declared flow graph (Phase M)

    Schematic of every value-flow path the spec declares: mint pools (⊕), burn sinks (⊖), per-role wallets, asset inventories (◆), and the events (◇) that drive each flow. Edge styles: solid · dashed (condition-gated) · double (DSL-driven) · dotted (event annotation). Disconnected sub-graphs surface as diagnostics below.

    Network analytics (Phase L1)

    Centralities computed on the interaction graph. Network-level statistics compared against two null models: G(n, p) matching the observed density (Erdős–Rényi) and the configuration model matching the degree sequence. Z-scores outside ±2 σ flag structural difference from random. Pearson correlations show whether centrality co-varies with balance (network position → economic outcome).

    Trade network at period 0

    Nodes are agents (size ∝ balance, colored as above); edges are realized transfers between agents up to this period. Force-directed: clusters indicate frequent trading partners. Use the controls to declutter — top-K shows only the heaviest edges; window shows only edges created in the last N periods.
