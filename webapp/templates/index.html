Token Economy Verifier

A pre-deployment diagnostic for community token economies, based on the six failure-mode framework (Domenicale & Avanzo & Schifanella, DLT2026).

How does this work?

The verifier checks your token-economy design against six formal sustainability conditions from §3 of the paper. For each condition, it either proves the condition holds across all plausible parameter values or returns a concrete counterexample — a parameter assignment that triggers the failure — together with a critical value showing exactly what you'd need to change.

The questions you answer fall into five groups (token design, emission, burn, governance, participants & network) plus seven non-functional requirements. Most parameters are structured choices; a few are numeric ranges. "I don't know" is a legitimate answer — the verifier searches across all plausible values for fields you can't pin down.

The verdict for each failure mode includes:

  • Status: pass, fail, pass-as-intended (when an NFR you declared makes the "failure" intentional), inconclusive, or not-applicable.
  • Critical value: the boundary parameter value at which the verdict flips. For example, FM4 (free-rider collapse) reports γ\* — the minimum monitoring capacity at which cooperation is structurally viable.
  • Recommendation: a concrete numeric instruction you can act on, plus the structured-choice mechanisms that satisfy the threshold.
  • Counterexample: a specific failing assignment with a binding-constraint indicator showing which clause failed.
